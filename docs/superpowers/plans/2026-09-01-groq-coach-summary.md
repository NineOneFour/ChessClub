# Groq Coaching Summary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate a plain-language, kid-facing post-game coaching summary for each player in a finished, Stockfish-analysed game, using Groq's `llama-3.3-70b-versatile`, and store it per `(game, player)`.

**Architecture:** The existing `analysis/worker.ts` process — after it finishes Stockfish analysis for a game and finds no more Stockfish work queued — claims the oldest analysed game missing a coaching summary for either player, builds a prompt from already-computed data (`performanceIn`, the player's costliest moves with SAN/FEN), calls Groq, and stores the result in a new `game_coach_summary` table. Coaching and Stockfish analysis are independent failure domains inside the one process: a Groq outage never touches `game_analysis`, and there is no interim "in progress" state to leak — a crash before a summary is recorded just means the next poll finds the same missing row.

**Tech Stack:** TypeScript, Drizzle ORM (`lib/db/schema/analysis.ts`), Postgres, `groq-sdk` (new dependency), the existing `tsx`-run smoke-script test convention (`scripts/smoke-*.ts`, no unit test framework).

**Spec:** `docs/superpowers/specs/2026-09-01-groq-coach-summary-design.md`

## Global Constraints

- No unit test framework in this project — verification is via `scripts/smoke-*.ts` scripts with `check()`/`skip()` helpers run against a real Postgres database, following the exact style of `scripts/smoke-analysis.ts`.
- No provider abstraction beyond one module boundary (`lib/llm/groq.ts`) — a second provider later means a second module with the same function signature, not a registry.
- No attempts cap / permanent-failure state for coaching — a failed attempt leaves `summary` null and is retried on a later poll indefinitely.
- Model: `llama-3.3-70b-versatile`, overridable via `GROQ_MODEL`. `GROQ_API_KEY` unset means coaching is skipped entirely; the rest of the app is unaffected.
- System prompt targets children aged 8-13.
- Stockfish work is always drained from the queue before any coaching work is attempted, so a Stockfish backlog is never slowed down by Groq calls.
- `.env` and `.env.example` already have `GROQ_API_KEY` / `GROQ_MODEL` entries — no task needed for that.

```ts
/**
 * One post-game coaching summary per player, generated by an LLM (Groq —
 * see lib/llm/) from this player's own performance in this game.
 *
 * One row per (game, player) rather than one per game: the two players'
 * summaries are different text about different people's play, not one
 * shared artifact. A row exists once generation has been attempted:
 * `summary IS NULL` (with `error` set) means "tried and failed, retry on a
 * later poll" — there is no attempts cap and no permanent-failure state, on
 * the same "leave it, retry next poll" reasoning as the rest of the analysis
 * pipeline, without the extra bookkeeping game_analysis needs for its
 * long-running 'running' state — coaching has no interim state to leak,
 * since generation either finishes and records a summary, or doesn't, and
 * the next poll just tries again.
 */
export const gameCoachSummary = pgTable(
  "game_coach_summary",
  {
    gameId: integer("game_id")
      .notNull()
      .references(() => games.id, { onDelete: "cascade" }),
    userId: integer("user_id")
      .notNull()
      .references(() => users.id, { onDelete: "cascade" }),

    /** Null while pending or after a failed attempt. */
    summary: text("summary"),
    /** Which Groq model produced `summary`. Null until a summary exists. */
    model: text("model"),
    /** The last failure, cleared on success. */
    error: text("error"),
    generatedAt: timestamp("generated_at", { withTimezone: true }),
  },
  (t) => [
    primaryKey({ columns: [t.gameId, t.userId] }),
    index("game_coach_summary_game_idx").on(t.gameId),
  ],
);
```

- [ ] **Step 1: Create `lib/services/coach.ts`**

```ts
import { and, eq, sql } from "drizzle-orm";
import { db } from "../db";
import { gameCoachSummary } from "../db/schema";

/**
 * Post-game coaching summaries, generated by an LLM from each player's own
 * Stockfish-derived performance in a finished game. See lib/llm/coach.ts for
 * what goes into a summary and lib/llm/groq.ts for who generates it — this
 * module only knows about the queue and the storage.
 *
 * There is no interim "claimed"/"running" state here, unlike
 * lib/services/analysis.ts's game_analysis queue: a coaching attempt either
 * finishes (recordCoachSummary) or doesn't (recordCoachFailure, or the
 * process dies before either runs), and in both non-success cases the next
 * poll simply tries again because no row — or a row with a null summary —
 * still reads as "needs coaching." Recording is an idempotent upsert, so two
 * workers racing on the same pair would waste one Groq call, never corrupt
 * data; that's a low enough stake, at this club's single-worker scale, not
 * to warrant the same for-update-skip-locked ceremony game_analysis uses.
 */

export type CoachClaim = { gameId: number; userId: number };

type CandidateRow = {
  game_id: number;
  white_id: number;
  black_id: number;
  white_summary: string | null;
  black_summary: string | null;
};

/**
 * The oldest finished, analysed game with a player still missing a summary,
 * and which of its two players needs one — white is offered first if both
 * do, so a follow-up poll picks up black.
 */
export async function claimNextForCoaching(): Promise<CoachClaim | null> {
  const rows = await db.execute(sql`
    select
      g.id as game_id,
      g.white_id,
      g.black_id,
      ws.summary as white_summary,
      bs.summary as black_summary
    from game_analysis ga
    join games g on g.id = ga.game_id
    left join game_coach_summary ws
      on ws.game_id = g.id and ws.user_id = g.white_id
    left join game_coach_summary bs
      on bs.game_id = g.id and bs.user_id = g.black_id
    where ga.status = 'done'
      and (ws.summary is null or bs.summary is null)
    order by ga.finished_at asc
    limit 1
  `);

  const row = (rows as unknown as CandidateRow[])[0];
  if (!row) return null;

  return row.white_summary === null
    ? { gameId: row.game_id, userId: row.white_id }
    : { gameId: row.game_id, userId: row.black_id };
}

/** Store a successful summary, replacing any earlier failed attempt. */
export async function recordCoachSummary(
  gameId: number,
  userId: number,
  summary: string,
  model: string,
): Promise<void> {
  await db
    .insert(gameCoachSummary)
    .values({ gameId, userId, summary, model, error: null, generatedAt: new Date() })
    .onConflictDoUpdate({
      target: [gameCoachSummary.gameId, gameCoachSummary.userId],
      set: { summary, model, error: null, generatedAt: new Date() },
    });
}

/** Record a failed attempt. `summary` stays null, so it is retried later. */
export async function recordCoachFailure(
  gameId: number,
  userId: number,
  message: string,
): Promise<void> {
  const error = message.slice(0, 500);
  await db
    .insert(gameCoachSummary)
    .values({ gameId, userId, summary: null, model: null, error, generatedAt: null })
    .onConflictDoUpdate({
      target: [gameCoachSummary.gameId, gameCoachSummary.userId],
      set: { error },
    });
}

/** The stored summary for one player in one game, or null if none exists yet. */
export async function summaryFor(gameId: number, userId: number): Promise<string | null> {
  const [row] = await db
    .select({ summary: gameCoachSummary.summary })
    .from(gameCoachSummary)
    .where(and(eq(gameCoachSummary.gameId, gameId), eq(gameCoachSummary.userId, userId)));
  return row?.summary ?? null;
}
```

```ts
import Groq from "groq-sdk";

/**
 * The one place that knows how to talk to Groq. `lib/llm/coach.ts` builds
 * what to say; this module only sends it. A second provider later is a
 * second module with the same three exports, swapped in at the one call
 * site in lib/services/coach.ts's caller (analysis/worker.ts) — there is no
 * registry to extend because there is nothing to register yet.
 */

const DEFAULT_MODEL = "llama-3.3-70b-versatile";

let cachedClient: Groq | null = null;

/** Whether coaching can run at all. Checked once at worker startup. */
export function isConfigured(): boolean {
  return Boolean(process.env.GROQ_API_KEY);
}

/** The model to use — GROQ_MODEL if set, else the default. */
export function model(): string {
  return process.env.GROQ_MODEL || DEFAULT_MODEL;
}

function getClient(): Groq {
  if (!cachedClient) {
    const apiKey = process.env.GROQ_API_KEY;
    if (!apiKey) throw new Error("GROQ_API_KEY is not set");
    cachedClient = new Groq({ apiKey });
  }
  return cachedClient;
}

/** One system/user exchange, no streaming, no tools. Returns the reply text. */
export async function complete(systemPrompt: string, userPrompt: string): Promise<string> {
  const response = await getClient().chat.completions.create({
    model: model(),
    messages: [
      { role: "system", content: systemPrompt },
      { role: "user", content: userPrompt },
    ],
  });

  const content = response.choices[0]?.message?.content;
  if (!content || content.trim().length === 0) {
    throw new Error("Groq returned an empty response");
  }
  return content.trim();
}
```

```ts

import { db } from "../db";
import { gameMoveAnalysis, gameMoves } from "../db/schema";
import * as games from "../services/games";
import { performanceIn } from "../services/ratings";
import type { GamePerformance } from "../chess/rating";
import { complete } from "./groq";

/**
 * Turns Stockfish's already-computed judgement of one player's game into a
 * prompt for Groq, and gets the coaching text back. Stockfish determined
 * what happened (performanceIn, the move grades); this module only explains
 * it — see the "AI Chess Coach" section of the project brief.
 */

const WORST_MOVES = 3;
const START_FEN = "rnbqkbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR w KQkq - 0 1";

export const COACH_SYSTEM_PROMPT = `
You are a friendly chess coach writing directly to a child, aged 8 to 13, \
about a chess game they just finished at a small private chess club for \
kids and their friends. A chess engine (Stockfish) has already analysed the \
game; your only job is to explain its findings in warm, simple, encouraging \
language a child that age can read and act on.

Rules you must follow:
- Never contradict or change any number, result, or move given to you in \
the message below — those come directly from the chess engine and are \
always correct.
- Never invent details (piece names, tactics, reasons) beyond what is given \
to you. If you describe why a costly move went badly, hedge it ("it looks \
like...", "that may have let...") rather than stating it as settled fact.
- Keep it short: 3-5 sentences, plain language, explain any chess word you \
use in the same breath. No markdown, no bullet lists, no move lists, no \
numbers copied verbatim — write it as prose a kid would enjoy reading.
- Be specific and encouraging, never harsh or generic: praise one real \
thing from the data given, and name one concrete thing to work on next.
`.trim();

type WorstMove = {
  ply: number;
  san: string;
  lossCp: number;
  fenBefore: string;
  fenAfter: string;
};

async function worstMoves(gameId: number, isWhite: boolean): Promise<WorstMove[]> {
  const rows = await db
    .select({
      ply: gameMoves.ply,
      san: gameMoves.san,
      fenAfter: gameMoves.fenAfter,
      lossCp: gameMoveAnalysis.lossCp,
    })
    .from(gameMoves)
    .innerJoin(
      gameMoveAnalysis,
      and(eq(gameMoveAnalysis.gameId, gameMoves.gameId), eq(gameMoveAnalysis.ply, gameMoves.ply)),
    )
    .where(eq(gameMoves.gameId, gameId))
    .orderBy(asc(gameMoves.ply));

  const fenBefore = (ply: number): string =>
    ply === 1 ? START_FEN : rows.find((r) => r.ply === ply - 1)?.fenAfter ?? START_FEN;

  return rows
    .filter((r) => r.ply % 2 === 1 === isWhite)
    .sort((a, b) => b.lossCp - a.lossCp)
    .slice(0, WORST_MOVES)
    .map((r) => ({
      ply: r.ply,
      san: r.san,
      lossCp: r.lossCp,
      fenBefore: fenBefore(r.ply),
      fenAfter: r.fenAfter,
    }));
}

function buildPrompt(input: {
  state: games.GameState;
  isWhite: boolean;
  performance: GamePerformance;
  worst: WorstMove[];
}): string {
  const { state, isWhite, performance, worst } = input;
  const you = isWhite ? state.white.username : state.black.username;
  const opponent = isWhite ? state.black.username : state.white.username;
  const myId = isWhite ? state.white.id : state.black.id;

  const outcome =
    state.winnerId === null
      ? "The game was a draw"
      : state.winnerId === myId
        ? "You won the game"
        : "You lost the game";

  const worstText =
    worst.length === 0
      ? "No notably costly moves were found."
      : worst
          .map(
            (m, i) =>
              `${i + 1}. Move ${Math.ceil(m.ply / 2)} (${m.san}) cost about ` +
              `${Math.round(m.lossCp / 100)} pawns of advantage.\n` +
              `   Position before this move (FEN): ${m.fenBefore}\n` +
              `   Position after this move (FEN): ${m.fenAfter}`,
          )
          .join("\n");

  return `
You are writing a coaching summary for ${you}, who just finished a chess game.

Result: ${outcome}, by ${state.resultReason ?? "unknown reason"}, against ${opponent}.

Performance this game, already computed by the chess engine — trust these numbers exactly:
- Estimated playing level this game: ${performance.rating ?? "not enough moves to estimate"}
- Moves played: ${performance.moves}
- Average centipawn loss: ${performance.acpl}
- Blunders: ${performance.blunders}
- Mistakes: ${performance.mistakes}
- Inaccuracies: ${performance.inaccuracies}
- Share of moves matching the engine's own top choice: ${Math.round(performance.bestShare * 100)}%

The costliest moves ${you} made this game:
${worstText}

Write the coaching summary for ${you} now, following the system instructions.
`.trim();
}

/** Build and send the coaching prompt for one player in one finished game. */
export async function generateCoachSummary(gameId: number, userId: number): Promise<string> {
  const state = await games.get(gameId);
  if (!state) throw new Error("the game is gone");
  if (state.status !== "finished") throw new Error("the game is not finished");

  const isWhite = state.white.id === userId;
  if (!isWhite && state.black.id !== userId) {
    throw new Error("that player is not in this game");
  }

  const performance = await performanceIn(gameId, userId);
  if (!performance) throw new Error("no analysis performance available for this player");

  const worst = await worstMoves(gameId, isWhite);
  const prompt = buildPrompt({ state, isWhite, performance, worst });

  return complete(COACH_SYSTEM_PROMPT, prompt);
}
```

```ts
/**
 * A deterministic legal game of `plies` half-moves that has not ended.
 * Copied from scripts/smoke-analysis.ts's helper of the same name — kept
 * local rather than shared, matching this project's one-file-per-suite
 * smoke script convention.
 */
function longLegalGame(plies: number): string[] {
  for (let seed = 1; seed < 500; seed += 1) {
    let state = seed;
    const next = () => (state = (state * 1103515245 + 12345) & 0x7fffffff);

    const moves: string[] = [];
    let usable = true;

    for (let ply = 0; ply < plies; ply += 1) {
      const position = rules.positionAfter(moves);
      if (position.ending) {
        usable = false;
        break;
      }
      const options = Object.entries(position.dests).flatMap(([from, tos]) =>
        tos.map((to) => `${from}${to}`),
      );
      if (options.length === 0) {
        usable = false;
        break;
      }
      moves.push(options[next() % options.length]);
    }

    if (usable && !rules.positionAfter(moves).ending) return moves;
  }
  throw new Error("could not generate a long legal game");
}
```
